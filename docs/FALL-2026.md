# Fall 2026 adoption: what to do before students use this site

Prepared October 28, 2026 from a review of this repository, the deployed site, and the `cs-300-content` Fall 2026 sources.
This is the working list for turning the site into the Fall 2026 practice track for Weeks 10 to 13.
Check items off here as they land, and move anything that becomes permanent into [MAINTENANCE.md](MAINTENANCE.md).

## Decisions this list assumes

- The site is called **CS300 Practice**, and each week's set of topics is that week's **Guided Practice**.
  "Lab" is reserved in the course for the graded AI Labs, so the word leaves the site name, the UI, and the content.
- The repository is renamed to match; `cs300-practice` is used below as the placeholder for whatever name is chosen.
- Fall 2026 is the only path students see this term.
  Spring 2027 stays in the repository but is not deployed.
- Nothing is graded here and nothing reports to D2L.
  D2L records only that a link was opened; the student's evidence is the workspace download and the progress export.

## A. Rename the repository and the URL

Renaming the GitHub repository changes the GitHub Pages address from `/cs300-react-lab/` to `/cs300-practice/`.
GitHub redirects the repository page, but it does not redirect the old Pages address, so every hardcoded path below must change in the same commit and the deploy must run before any link is posted in D2L.

- [ ] Rename the repository on GitHub, then update the local remote with `git remote set-url origin`.
- [ ] Confirm Pages is still enabled with the source set to GitHub Actions after the rename.
- [ ] `vite.config.js`: `base: "/cs300-practice/"`.
- [ ] `playwright.config.js`: both `/cs300-react-lab/` occurrences in `baseURL` and `webServer.url`.
- [ ] `tests/runner.spec.js` line 200: the runtime URL pattern.
- [ ] `scripts/export-d2l.mjs`: `SITE_URL`.
- [ ] `package.json`: `name`.
- [ ] `README.md`: the title, the deployed address, the dev server path, the harness paths, and the export section.
- [ ] `docs/CONTRACTS.md` section on `base`, and the repository name and address in `docs/DESIGN.md`, `docs/KICKOFF.md`, and `docs/PHASE2.md`; these are historical and may instead carry one line saying the repository was renamed.
- [ ] `.claude/launch.json` needs no change; it uses the port only.
- [ ] Rebuild and re-run `npm run export:d2l -- fall-2026` so every link in `dist-d2l/` carries the new address.

## D. Tie each topic back to the course

Every topic has reading links to react.dev, MDN, or Vite, but none has a `lecture` link, so the D2L export lists no course material under a topic.

- [ ] Decide what a `lecture` link points at.
  D2L Page URLs need a login and can change when a Page is recreated, so they are a poor target.
  If the public notes site publishes `content/notes/fall-2026/week-10/session-1.md`, link each topic to its session notes there; otherwise leave lecture links out and let the D2L Lesson carry the pairing.
- [ ] If links are added, put them on `topic.json` for Weeks 10 to 13 and re-export.
- [ ] Consider a `session` field (1 or 2) on each unit topic entry in the path file, so `export:d2l` can group a week's topics by session and the content repository's D2L guide generator can place each Weblink in the matching Lesson.
  Without it, the export page lists the topics in one ordered list and the Lesson placement is done by hand.

- [ ] Walk all five Week 10 topics on the deployed site as a student, in order, running every step and every check, with the inspector open on the React steps.
  This is the content review the course applies to every other student-facing file and has not happened for this site.

- [ ] Start `deploy.yml` by hand after the rename and the path changes land, and confirm the new address serves the site and the old one is gone from every link you hold.
- [ ] Open the site on a phone once; the step page is built for a 320 pixel column but has not been checked on a real device this term.
